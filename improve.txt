LinguaLink Backend Improvements
Enhance the backend AI pipeline, API surface, and code quality without touching any files in frontend/ or static/. The frontend team's changes will merge cleanly.

What We're Improving
The current backend is functional but minimal. Key gaps:

No result caching — every request re-runs the full ML pipeline (slow)
No async/background task support — large CSV uploads block the server
Matcher weights are hardcoded — can't tune from the API
Single embedding model — no fallback or model selection
No confidence explanation — pairs returned with scores but no human-readable reason
No batch record comparison — can only compare a single query vs dataset
No deduplication export — results can't be downloaded as CSV/JSON
No API rate metrics — no visibility on pipeline performance per signal
Phonetic engine is basic — uses only a simple metaphone skeleton; no Soundex/NYSIIS consideration
Fuzzy engine single-pass — token_set_ratio not included (better for subset matching)
No in-memory result store — results are ephemeral, can't re-fetch
No GET /api/results/{job_id} — no way to poll previously run jobs
Proposed Changes
New Modules
[NEW] app/cache.py
In-memory LRU job result cache. Stores recent pipeline results by a job_id so the frontend can poll or re-fetch without re-running the pipeline.

[NEW] app/explainer.py
Generates human-readable duplicate explanations: "High semantic similarity (0.89) + phonetic match → likely transliteration duplicate". Considers all three signals and produces a reason label + confidence_tier (high / medium / borderline).

[NEW] app/background.py
FastAPI BackgroundTasks-based async job runner. Accepts a CSV upload, queues the pipeline, returns job_id immediately. Client can GET /api/jobs/{job_id} to poll status (pending / running / done / error).

Modified Files (backend only)

Rebalance weights: ratio=0.3, partial=0.25, token_sort=0.25, token_set=0.20
